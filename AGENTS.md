# AGENTS.md

Инструкции для ИИ-агентов (Claude Code, Codex, Cursor и др.), работающих в этом репозитории.

## Назначение проекта

Валидатор и нормализатор полного журнала заявок (OrderLog) Мосбиржи на C++20.
Ядро читает CSV, нормализует цену (int64-шаги) и время (наносекунды), восстанавливает
стакан и применяет каталог правил с исходами `pass / repair / quarantine / reject`.
Ядро детерминировано: никаких сетевых запросов, случайности и зависимости от текущего времени.

## Структура

- `include/olv/` — публичные заголовки, документируются Doxygen-комментариями `///`.
- `src/` — реализация библиотеки `olv_core`.
- `app/main.cpp` — CLI `olv`.
- `tests/` — GoogleTest; фикстуры в `tests/data/`.
- `bench/` — Google Benchmark.
- `docs/adr/` — архитектурные решения.
- `.github/workflows/` — CI и публикация документации.

## Команды

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release   # конфигурация
cmake --build build -j                            # сборка
ctest --test-dir build --output-on-failure        # тесты
./build/bench/olv_bench                           # бенчмарк
./build/olv tests/data/sample_orderlog.csv 0.01   # CLI
```

## Правила оформления кода

- C++20, без расширений компилятора; сборка без предупреждений с `-Wall -Wextra -Wpedantic`.
- Отступ 4 пробела, строки до 100 символов.
- Типы `PascalCase`, функции и переменные `snake_case`, приватные поля с суффиксом `_`,
  константы `kCamelCase`.
- Весь код в пространстве имён `olv`.
- Цены и объёмы хранятся только в целых числах (`std::int64_t`); `double` для цен запрещён.
- Ошибки разбора возвращаются через `std::optional` / отчёт, а не исключения в горячем пути.
- Каждая новая публичная функция или класс получает Doxygen-комментарий в заголовке.

## Ограничения для агента

- Перед завершением задачи собери проект и запусти тесты; задача не завершена, пока
  `ctest` не проходит.
- Новое правило валидации или изменение движка стакана требует unit-теста.
- Не меняй файлы в `.github/workflows/` и `Doxyfile` без явного запроса.
- Не меняй ожидаемые значения в эталонном тесте `Replay.SampleFixtureOracle` и
  `tests/data/`, чтобы тест прошёл; если ожидания неверны, объясни почему и спроси.
- Не добавляй новые внешние зависимости без запроса (особенно Arrow/Parquet, Boost).
- Не добавляй сетевой код в ядро; загрузка из MOEX ISS живёт в отдельных скриптах.
- Не коммить большие файлы данных (реальные OrderLog) в репозиторий.
- Не делай push в `main` и не переписывай историю без запроса.
